# City仕様

## City在庫

- 同じCity Groupの2Nodeは、1つの`CityNodeContent`と在庫を共有する
- ラインナップはMap生成時に確定し、Run中は再抽選しない
- 商品は1個ずつ独立した在庫Entryとして保持する
- 購入済みEntryは削除せず、`isPurchased`を保持して売り切れ表示にする

```text
CityStockEntry
- stockId
- itemId
- basePrice
- price
- isPurchased
```

## ラインナップ構成

Map生成時に全City分の商品Deckを作り、Run Seedでシャッフルして各Cityへ振り分ける。
商品数の保証や均等配分はCityごとの独立抽選ではなく、全Cityを対象に行う。

| Category | 商品Pool | 現在の振分け案 |
|---|---|---:|
| 薬局 | きずぐすり | 全Cityへ合計40個 |
| 薬局 | MNポーション | 全Cityへ合計40個 |
| 薬局 | 元気のかけら | 全Cityへ合計40個 |
| 技マシン | 無属性Skill | 各Cityへ同数 |
| 技マシン | 属性Skill | 各Cityへ同数 |
| 技マシン | 技忘れマシン | 全Cityへ合計16個 |
| 刻印屋 | 8属性 / MaxHP / MaxMN / SPD / HST / DB / RBの刻印 | 各Statを各Cityへ平均4個ずつ |
| 装備品 | 冠 / 勾玉 / 靴 × 8属性 | 全48個を各Cityへ6個ずつランダムに振り分け |

`v0.8.1`では、各Cityへ無属性技マシン1個と属性技マシン1個を最低限配置する。
未実装の商品Poolは、対応するItemと効果が実装されるまで在庫へ混ぜない。

- きずぐすりは対象のHPを基準値`500`だけ回復する
- MNポーションは対象のMNを基準値`500`だけ回復する
- 元気のかけらは戦闘不能の味方Pachimonだけを対象とし、基準値`500`のHPで復活させる
- 元気のかけらのBasePriceは`1500 Gold`とする
- 回復量は使用時に計算し、最大値を超えた分は切り捨てる

回復Itemは固定値回復を基準とし、後半Cityほど上位Itemを増やす補正は一旦保留する。
商品種類が増えた段階で、CityのRowに応じた重み付き抽選が必要か再検討する。

## 生成Itemの個体差

- 刻印には、狙ったStatを強化する主効果と、ランダムな代償を持たせる
- 装備品には装備Slotを持たせ、将来は冠 / 勾玉 / 靴をそれぞれ1つ装備可能にする
- 各部位・各属性を2個ずつ作り、`3部位 × 8属性 × 2 = 48個`をRun全体へ配置する
- 48個をまとめてシャッフルし、8つのCityへ6個ずつ配る
- City単位では部位数・属性数を保証しないため、冠が6個並ぶ場合も許容する
- ランダム効果はItem定義ではなく、Map生成時に個々の商品Entryへ確定する
- 装備はCityのMainPaneで購入し、選択したPachimonへ直接装着する

```text
GeneratedItemData
- itemId
- primaryEffectValue
- statChanges[]
- equipmentSlot (装備品のみ)
```

`CityStockEntry`は`itemId`だけでなく`GeneratedItemData`を保持し、購入時に同じデータを
`ItemInstance`へ渡す。これにより、在庫表示・購入・所持・使用・将来のSave / Loadで同じ効果を参照する。

## 価格

- 各商品の価格は`BasePrice`の70%から130%に収める
- 価格は個々の在庫Entryごとに異なる
- 価格差の合計はItem種類ごとではなく、City内の全在庫を対象に0とする
- City内の実売価格総額は、そのCityに並ぶ全商品のBasePrice総額と必ず一致する
- 高額Itemも同じ計算へ含める

これにより、きずぐすり全体が安く、技マシン全体が高いCityも生成できる。

技マシンのBasePriceは一律`1000 Gold`とする。
技忘れマシンのBasePriceは仮に`500 Gold`とし、全Cityへ合計16個を配置する。

## 効果量の揺らぎ

- 薬局Itemと刻印は、基準効果量の70%から130%で個別に揺らす
- きずぐすり、MNポーション、元気のかけらは、基準値`500`に対して`350`から`650`になる
- 同一Item・同一City内の効果量合計は、基準効果量の合計と一致させる
- 価格と効果量は別々の乱数で生成する
- 生成後にそれぞれを昇順へ並べ、同じ順位同士を組み合わせる
- 高価格の商品ほど効果量が低くならないことを保証する
- 比例式にはしないため、商品ごとの費用対効果には差が生じる
- ランダムな副作用は価格順位へ含めない

刻印の主効果は、Player Status報酬の2枠目と同じ価値を基準にする。

| 対象Stat | 主効果Base | 主効果範囲 |
|---|---:|---:|
| 8属性 | 30 | 21～39 |
| MaxHP / MaxMN | 180 | 126～234 |

代償は、ランダムに選ばれた対象Stat自身のBaseへ、主効果と同じRoll倍率と50%を掛ける。
これにより、異なるStat間でも報酬価値を基準に「主効果の半分」へ揃える。

```text
主効果 = floor(主効果対象Base × Roll倍率)
代償   = -max(1, floor(代償対象Base × Roll倍率 × 50%))
```

主効果と同じStatは代償候補から除外する。価格順位は主効果だけを基準とし、代償は価格へ反映しない。

商品名は実際の効果量を含め、`きずぐすり（+500）`、`炎の刻印（+30）`の形式で表示する。

刻印のBasePriceは一律`500 Gold`とし、実プレイ後に再調整する。

### 装備品

装備品のBasePriceは一律`2000 Gold`とする。主属性は8属性から装備定義ごとに固定し、
追加属性は主属性以外から商品生成時にランダムで決める。

| 部位 | 表示名 | 主属性 | 追加効果 |
|---|---|---:|---|
| 頭 | 冠 | 刻印6個分、80%～120% | 別属性を実際の主属性値の1/3 |
| 胴 | 勾玉 | 刻印3個分、80%～120% | 別属性を実際の主属性値の1/3、HST対応率を刻印4個分増加 |
| 足 | 靴 | 刻印3個分、80%～120% | 別属性を実際の主属性値の1/3、SPD対応率を刻印4個分増加 |

刻印1個分は属性`30`、SPD / HST`10`を現在の基準値とする。
各Cityの装備6個は、冠を2倍する前の主属性値と価格をそれぞれ昇順に並べ、同じ順位同士を組み合わせる。
これにより、部位にかかわらず高価格な装備ほど基準主効果が低くならないことを保証する。
RightPaneの装備品も価格昇順で表示する。
購入後にItemSlotへ入れる方式は採用せず、刻印と装備はCity内で対象Pachimonへ直接適用する。
装備品はMainPaneの装備屋から対象Pachimonを選択して購入・装着できる。

## RightPane

- Cityへ移動する前から全ラインナップを閲覧できる
- 商品は薬局 / 技マシン / 刻印屋 / 装備品の大CategoryごとのAccordionへまとめる
- 薬局では同名Itemを小Categoryとしてまとめる
- 刻印屋では対象Statごとの小Categoryへまとめる
- 刻印屋の小Categoryは`MaxHP / MaxMN / 炎 / 毒 / 水 / 氷 / 草 / 風 / 電 / 竜 / SPD / HST / DB / RB`の固定順とする
- 刻印屋は在庫が1個または0個でも対象Statの小Categoryを表示する
- 刻印の商品行は`炎の刻印（炎Icon+XX / 副作用対象Icon-XX）`の形式で主効果と副作用を表示する
- Iconのない`MaxHP / MaxMN / SPD / HST / DB / RB`は、Status表示と同じ背景色付きTextラベルを使用する
- 商品数が増えても、閉じた小Categoryの明細は一覧へ展開しない
- 商品の名前・価格部分をClickすると、Skill / Passive詳細と共通のOverlayへItem詳細を表示する
- City滞在中かどうかを問わず、全Categoryのラインナップを同じ形式で表示する
- RightPaneは在庫閲覧と商品詳細の確認専用とし、購入操作は置かない
- MainPaneで購入した商品は、RightPaneにもリアルタイムで売り切れ表示を反映する
- Cityへ入った時点から進行可能で、何も買わずに終了できる

## MainPane

City滞在中は、最初にShop選択画面を表示する。

```text
[ 薬局 ] [ 技インストラクター ]
[ 刻印屋 ] [ 装備屋 ] [ 進む ]
```

- Shopボタンで対象Categoryの画面へ遷移する
- `進む`はMapを開くだけで、Cityの利用を終了しない
- 次Nodeを決定する前なら、Mapを閉じることでCityの利用を再開できる
- Cityの利用終了は、次Nodeの決定時とする

各Shop画面は、左上にShop名、中央に商品、最下部中央左に戻るボタン、
最下部中央右に購入または次操作のボタンを配置する。

### 薬局

- きずぐすり、MNポーション、元気のかけらを商品種別ごとの列へ価格順で表示する
- 各商品にCheckBoxを置き、複数選択できる
- 購入ボタンに`購入 合計XXXX Gold`の形式で選択中の合計金額を表示する
- 合計価格が所持Goldを超える場合は`残高不足`として購入不可にする
- 選択数が空きItemSlot数を超える場合は`バッグがいっぱいだ！`として購入不可にする
- 一括購入は全成功または全失敗とし、一部だけ購入される状態を作らない

### 刻印屋

- 複数の刻印をCheckBoxで選択できる
- 選択中の合計金額を表示する
- 右下ボタンは`パチモンを選択`とする
- 選択した複数の刻印は、Pachimon選択Overlayで選んだ1体へまとめて適用する
- Gold消費、在庫の売り切れ化、全刻印の適用を1つの確定処理として行う
- 刻印はItemSlotへ追加しない

### 技インストラクター

- 技マシンをItemとして購入せず、その場で対象PachimonへSkillを習得させる
- 商品ごとに`パチモンを選択`ボタンを置く
- Skillを6個習得済みのPachimonは選択不可とし、`これ以上おぼえられない`と表示する
- 対象Skillを習得済みのPachimonは選択不可とし、`すでにおぼえている`と表示する
- 技忘れの場合、Skillが0個のPachimonは同様に選択不可とする
- 技忘れは`Pachimon選択 -> Skill選択`の2段階とし、同じOverlay内で内容を切り替える
- Skill選択画面には`戻る / 詳細を見る / 忘れる`を置く
- Skillは同一個体へ重複習得できない
- 最後の1Skillも忘れられ、Skillが0個になったPachimonは次回の対象選択で無効化する
- Gold消費、技忘れ、在庫の売り切れ化は1つの確定処理として行う
- 技マシンItem自体は、別のEventなどで使用する可能性があるため定義を維持する

### 装備屋

- 商品ごとに`パチモンを選択`ボタンを置く
- 対象装備Slotが埋まっているPachimonは選択不可とし、その理由を表示する
- 装備はItemSlotへ追加せず、購入確定時に対象Pachimonへ直接装着する

## Pachimon選択Overlay

- 所有Pachimonを横並びで表示する
- PachimonをClickして1体選択する
- 下部左に戻るボタン、下部右に決定ボタンを配置する
- Cityでは決定ボタンに購入金額を表示する
- 用途ごとに選択可能判定と選択不可理由を渡せる共通Viewとする
- 将来、Battle Rewardの対象選択も同じOverlayへ統合できる構造にする

購入確定後はMainPaneとRightPaneの双方を同じ`CityStockEntry`から再描画し、
売り切れ状態、所持Gold、残り商品の購入可否を同期する。

`v0.8.1`ではMainPaneからCityの商品を購入・適用できる状態を必須とする。

## 保留

- Cityの商品行へItem Iconを表示するか
- Item Icon自体を将来も維持するか

v0.7の商品行は文字中心で作り、後からIconを追加できる構造にする。
