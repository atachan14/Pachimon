# Party Progression

## 基本方針

- Player Partyは`1体 -> 2体 -> 3体`の順に増加する。
- Enemy Partyも進行に応じて`1体 -> 2体 -> 3体`へ増加する。
- 加入候補数は初期値として`3体 -> 6体 -> 9体`とし、プレイテスト後に調整する。

## StartNode
3体の選択肢から1体を選択に変更
セリフも
「ここに3匹のパチモンがおる。
1匹選びなさい。」
に変更。

1匹目選択（RightPaneでの選択ボタン（"X匹目"は無しにする）か、Expandedでは選択中にもう一度クリックも可。既存通り。）で進行。
「XXX（パチモン名）でよろしいか」
→はい/いいえ
あとは既存通り。

## row10.5くらいにライバル配置
Map上ではrow10とrow11の間にnode1つ分の距離を余分に開ける。
row10からrow11へのEdgeは通常Map生成時の接続を維持し、どのEdgeを選んでも通過時にライバル戦が割り込む。
境界には水平の点線を引き、右端にライバル、左端に博士を表示する。
そのスペースの一番右にライバルIconを配置。
左に博士Iconを設置。
ライバルIconクリックで既存battleNode同様にRightPaneでライバルのPachimon等の確認可能。
博士Iconクリックで、StartNodeでのRightPaneっぽく入手可能パチモンの確認が可能。

row10からrow11へ進む際、ライバルが現在進行中のNode間に、右からスライド移動してくる。で、BattleNode同様のbattleに突入。
加入するパチモンを選び終えた後は自動でrow11へ進まず、Mapを再表示する。プレイヤーがrow11の行き先を選び直した時点で通常の移動を再開する。

`row10.5`は表示上の座標とする。Encounterは経路を集約するNodeにせず、選択したEdgeと行き先を保持したまま必ず割り込む境界イベントとして扱う。

ライバル戦勝利報酬獲得後、StartNodeっぽく博士が再登場。
「ライバルを倒したようじゃな」
→「おう」ボタン
「ここに6匹のパチモンがおる。
新しい仲間を選びなさい。」

後は既存通り。

## row20.5くらいにパチパチ団配置
ライバルのときと同じ。
倒したら9匹の選択肢から1匹を選ぶ。

`row20.5`も表示上の座標とし、row20からrow21への既存Edgeを維持した必須の境界イベントとして扱う。
パチパチ団戦後の加入選択でもMapを再表示し、row21の行き先を選び直す。

## 追加時の並び順

原則、最初のパチモンが先頭で、追加毎に後ろに並んでいく。（ライバルでの追加パチモンが真ん中で、パチパチ団での追加が最後尾）
EventNodeでパチモンを並び替えるイベントを予定。
既存通り、途中での並び替えは原則不可（特定のEvent除く）

## 加入候補の生成・選出ルール
Map生成時にStartNode同様に行う。

- Run Seedから再現可能にする。
- Start、ライバル戦後、パチパチ団戦後の全18候補でSpeciesを重複させない。
- この全候補Species一意ルールはv0.8.2以降も維持する。
- そのため、現在のPlayer Partyと同じSpeciesや、過去に選ばれなかった候補Speciesも後の加入候補には出さない。
- 道中のEnemy、ライバル、パチパチ団として登場したSpeciesも候補になってよい。
- 加入候補とEnemyは、同じSpeciesでも別のPachimon Instanceとして扱う。

## 加入時のSkill・Passive・Stat
原則、既存と同様。
ただしSkillのみ変更。
row0-10：2つ（固定Skill+同属性Skillランダム）、かつAOEスキルを含めない。固定スキルがAOEのパチモンも登場しない。敵パチモンとしても登場しない。
row11以降：既存通り。

row0-10では、AOEだけでなく、単体戦で主要効果が成立しないSkill・Passiveを持つSpeciesも加入候補とEnemyから除外する。

例：

- 複数の味方または敵を必要とする。
- 前後の味方を参照する。
- 隊列移動を主要効果とする。
- 複数対象への連鎖を主要効果とする。
- 味方の戦闘不能を主要な発動条件とする。

ライバル戦後の加入候補は、加入後にrow11へ進むため、row11以降の通常Loadoutで生成する。

### 加入時のStatについて
既存通り。選択時、トレーナーStatによる増減も反映した状態で表示する。

- TrainerStatとBadgeは個体の基礎Statへ焼き込まず、既存のEffective Stat計算で反映する。
- 新規加入PachimonはEffective MaxHP / MaxMNで全快加入する。
- 新規加入時に既存PartyのHP / MNは回復しない。

## 敵
row1-10まではEnemyのPartyも1体。
row11-20ではEnemyのPartyも2体。
row21以降は既存通り。

## Battle報酬

- Skill・Passive候補は、既存通り倒したEnemyの戦闘開始時Loadoutから導出する。
- Enemyが1体または2体の場合、存在しないEnemy枠をダミー候補で補充しない。
- そのBattleで実際に得られる候補だけを表示する。
- Reward UIはEnemy数が1体・2体・3体のすべてで成立させる。
- Gold、Item、TrainerStatus、Badgeなど、Enemy数に依存しない報酬は既存仕様を維持する。

## プレイテスト調整項目

- `3体 -> 6体 -> 9体`の候補数がCompactでも過剰でないか。
- 1体Battleと2体Battleの期間が長すぎないか。
- 序盤のSkill・Passive候補が単調にならないか。
- Enemy数減少により、Skill・Passive報酬の選択肢が不足しすぎないか。
- ライバル戦後に通常LoadoutのPachimonが加入することで、既存メンバーとの格差が大きくならないか。
